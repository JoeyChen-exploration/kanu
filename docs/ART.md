# 卡奴美术需求表

2026-11-18 定：美术由我们自己做，不再交给服主。这份表列出要画什么、什么规格、用什么方式做、先做哪些，以及做好的图放在哪、怎么命名、怎么验收。

2026-11-25 更新：合并美术那边的版本，加入制作方式（AI / 代码 / 后期）、AI 出图规范、头像规范、封壳和品牌图的命名、源文件存放；卡面安全区、联系人 id、导入流程、验收规则以仓库实现为准。

## 总体要求

- **风格**：反乌托邦空间站下层区，霓虹、赛博朋克、旧货店的感觉。不要做成文字游戏：柜台、库存、开包都要有画面。紫色霓虹只作边缘光（呼应 Activity 图标），**主色调由系列决定**（见"风格基准"和系列表）。界面和卡框仍用暗物质 K 的深紫配色。
- **配色**：界面和卡框是一套视觉，具体色值放在 `art-src/palette.json`：深底 `#030207 → #0d0619 → #241046`（径向渐变，中心亮），霓虹描边 `#b48cff`，外发光 `#4a1fd1`，高光 `#e6d7ff`，金框 `#fff3c4 → #e8b84a → #8a5a12 → #f7d77a`，镭射 `#7cf7ff → #b99bff → #ff8ad8 → #ffe28a`。标志字体 Unbounded 900。
- **横屏**：卡奴是横屏游戏，主要在手机横屏（约 844 × 390）和电脑 16:9 上看。场景背景、界面底图按横版画。
- **格式**：WebP（要透明的用带透明通道的 WebP 或 PNG）。体积上限：场景背景 300 KB，其余单张 150 KB。所有图由卡奴服务器自己托管，不引用外部链接。
- **分层，能复用就复用**：卡面和卡框分开画，每张卡只画一次卡面，6 套卡框由前端叠加，所以是"100 幅卡面 + 6 套卡框"，不是 100 × 6 张。放大镜看到的细节也是一套通用贴图，所有卡共用（见下）。
- **图里不放文字**：卡名、系列名、价格、序列号、印章上的字，一律由前端渲染，或者在后期统一加。AI 画不准中文，而且文字放在图里以后就改不了。
- **原创**：不画现有作品的角色、品牌标志和吉祥物。评级封壳可以参考真实评级卡的"透明壳 + 顶部标签"结构，但标签版式、配色、标志都要是我们自己的。
- **优先级**：MVP = 第一版内测就要；后期 = 以后的版本，不急。

## 卡面安全区

卡牌在游戏里按 **630 × 880** 为基准排版，所有位置都按卡宽的比例换算（`style.css` 卡牌一段用容器单位写，1% 卡宽 = 6.3 px），所以不管卡显示多大，下面这些像素值都准。卡框的镂空、卡面构图都照这张表；改了要同时改 `style.css`、`art-src/palette.json` 的 `layout`。

| 区域 | 位置（x, y 从左上角起，单位 px） | 说明 |
| --- | --- | --- |
| 整张卡 | 0, 0 – 630, 880，外圆角 28 | **卡面图画满整张**，边缘也要有画面，不能留白边 |
| 外框带 | 四周 24 px | 被卡框盖住，卡面图这一圈只要有颜色延续就行 |
| 卡面窗口 | 24, 24 – 606, 856，圆角 20 | 透过卡框看到的卡面 |
| 稀有度角标 | 40, 40 – 160, 160（120 × 120） | 左上，盖在卡面上 |
| 序列号 | 430, 48 – 590, 108（160 × 60） | 右上，只有编号限定卡有 |
| 拒评印章 | 480, 116 – 590, 156 | 右上，序列号下面，只有被拒评的卡有 |
| 名牌条 | 24, 704 – 606, 856（高 152） | 卡框画半透明深色底；卡名在 716–772，标签在 780–812。这里只放背景，不放关键内容 |
| 风格标签 | 476, 818 – 590, 848 | 名牌条右下，"闪卡""金框"之类 |
| "批"字标记 | 36, 800 – 84, 848 | 名牌条左下，批发来的卡才有 |
| **主体安全区** | **60, 176 – 570, 690** | 人物的脸、物件的主要部分都放在这里面，不会被角标和名牌条挡住 |

**人物卡取景到膝盖以上或腰部以上**（2026-11-25 定）：画人物的卡不画全身，免得腿和脚伸进名牌条被卡名盖住。提示词里写 `waist-up portrait`（腰部以上，原来写"半身像"的都改成这个）或 `three-quarter shot from the knees up`（膝盖以上）。配合"底部五分之一只放地面或背景"，人物的脸和上半身落在主体安全区里。

小卡（卡册格子里约 90 px 宽）不显示标签和风格标签，只有卡名，其余位置不变。

## AI 出图规范（Draw Things）

- **模型**：先用 SDXL 类模型跑通，风格定下来后换成社区微调版（如 Juggernaut XL），之后不要中途换模型，否则风格会断。
- **尺寸**：卡面用 832 × 1152 生成（导入时居中裁成 630 × 880）；头像、联系人用 1024 × 1024 生成（导入时缩到 256 × 256）；场景用 1344 × 768 生成，先用 Draw Things 自带的放大功能放大，导入时再缩放到 1920 × 1080（没放大也能导入，但会糊一些）。
- **负面提示词**（所有图都加）：`photo, photorealistic, photograph, 3d render, text, letters, words, watermark, signature, logo, frame, border, card frame, blurry, lowres, extra fingers, deformed hands`
  - **出 GNG（地下帮派）卡时**，负面提示词临时再加 `purple, violet, magenta`：风格基准里的紫色边缘光容易把帮派的红黄钨丝灯染紫。只加在负面提示词里，正面提示词不写"no purple"（2026-11-25 改）。
- **画风锚点**：卡面提示词在主体描述后面紧跟 `painterly digital illustration`，防止出成照片或 3D 渲染。
- **卡面构图**：每条卡面提示词都带"底部五分之一只放地面或背景"（`bottom fifth of the image is empty floor or background only, no figures near the bottom edge`），避开名牌条（y 704 以下）；主体居中，放在主体安全区里。
- **记录**：每张原图的模型、提示词、负面提示词、种子、步数、尺寸由 `npm run art:import` 从 PNG 自带的元数据里自动读出，写进 `art-src/prompts.csv`，不用手记。以后要重画、补画同系列的卡，照着这张表就能对上风格。原图如果没有元数据（比如在别的软件里另存过），导入时会提示，在原图目录的 `prompts.csv` 里手动补一行。
- **挑图**：每张至少出 4 张备选，挑一张；N / R 卡可以放宽，SR 以上要精挑。

### 风格基准

```
cyberpunk trading card art, concept art, dystopian space station, subtle violet neon rim light, highly detailed digital painting
```

每个系列加一句系列风格（英文原样，是提示词的一部分，决定这个系列的主色调）。100 张卡的完整提示词（主体 + 构图 + 系列风格 + 稀有度 + 通用风格，按出图优先级排好）在 `art-src/card-prompts.csv`，是卡面提示词的源头：

### 头像规范

- 半身像，正面略侧，眼睛在画面上方三分之一处。
- 背景统一：深色虚化的店铺内景，带一点紫色霓虹光。
- 每类顾客的变体换脸、发型、衣着，但保持同一类的标志性特征（如富人的毛领、主播的直播灯、黑市中间人的兜帽）。
- 科技树联系人用同一套构图，和顾客头像放在一起不跳。

## 先做哪些

想尽快让游戏"有画面"，建议按这个顺序：

1. 场景背景（柜台、台面）+ 5 种卡包包装：一打开就能看到。（卡背已生成）
2. 道具（放大镜、电话）。（4 套卡框 + 稀有度角标已生成）
3. 卡面插画：先每个系列画 SR 以上的几张（玩家最在意开到的好卡），N / R 可以晚一点。先出十几张，风格稳定了再批量做。
4. 顾客头像、封壳。（放大镜细节、磨损已生成）
5. 其余。

**AI 图的流程（Mac 出图 → Windows 接入）**：

1. Joey 在 Mac 上用 Draw Things 出图，挑好的原图（PNG）放进网盘同步的原图目录（各类别子目录）。原图目录**根目录**的文件（`prompts.csv`、`card-prompts.csv`、`README.txt`、`icon-1024.png` 等）不当原图处理，导入时忽略。文件名和 `public/art/` 一一对应，只是扩展名是 `.png`：`cards/NEO-01.png` → `art/cards/NEO-01.webp`。
2. Windows 这边 `.env` 里写 `ART_RAW_DIR=<原图目录>`（见 `.env.example`），跑 `npm run art:import`：
   - 只处理新增或改过的原图（比较修改时间）；
   - 按规格处理：卡面居中裁成 63:88 再缩到 630 × 880，顾客头像、联系人缩到 256 × 256，场景缩放到 1920 × 1080，卡包包装等比缩到 630 × 880 以内；
   - 转 WebP，质量从 85 往下试，直到满足体积上限（场景 300 KB，其余 150 KB）；
   - 从每张原图的元数据读出生成参数写进 `art-src/prompts.csv`；原图目录里手记的 `prompts.csv` 也会合进去；
   - 处理完自动跑 `npm run art:check`，打印新增了哪些图、哪些超标或命名不对。
3. 看一眼游戏里的效果，提交 `public/art/` 和 `art-src/prompts.csv`。

**代码图的流程**：改 `scripts/art/build.mjs` 或 `art-src/palette.json`，跑 `npm run art:build`，SVG 源码进 `art-src/svg/`、成品进 `public/art/`。

**缺图时**：前端每类图加载失败都回退到现在代码画的占位，不报错，所以可以一张一张地放。已经接图的：卡面、卡框、稀有度角标、卡背、卡包包装（含整盒）、顾客头像、放大镜细节、磨损。场景、道具、封壳、卡册、图鉴册、珍藏柜、联系人、UI 图标等图到了再接（代码里还是占位）。

## 验收（`npm run art:check`）

检查 `packages/client/public/art/` 里的每张图，有问题退出码 1：

- 只收 `.webp` / `.png`，扩展名要和文件内容一致；同一张图 `.webp` 和 `.png` 只能留一个。
- 必须放在 `art/<类别>/` 下面一层，类别和文件名按上面的命名表：卡编号要在 `content/series/*.json`（`art-src/cards.json`）里，顾客类型要在 `CUSTOMER_TYPES` 里，风格、稀有度、放大镜细节、联系人、封壳只能是表里那几个名字。
- 尺寸：卡面、卡背、卡框、磨损 630 × 880；稀有度角标正方形；顾客头像、联系人、放大镜细节 256 × 256；卡包包装竖版；场景横版、至少 1920 × 1080。
- 透明通道：卡框、稀有度角标、放大镜细节、磨损、封壳、阵营徽记和关系等级、UI 图标、道具、科技树图标、Logo 必须带。
- 体积：场景 ≤ 300 KB，其余 ≤ 150 KB。
- `art/brand/` 只用来上传 Developer Portal，整个目录跳过不检查。
- 最后打印 MVP 各类图的进度（比如"卡面 12 / 100"）。
