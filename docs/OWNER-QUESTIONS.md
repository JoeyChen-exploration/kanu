## 1. 卡奴是什么

一个跑在 Discord Activity 里的卡牌店经营小游戏，形式和旺财牌局一样：在 Discord 里点开网页小程序玩。

- **玩法**：玩家开一间卡牌店。花游戏内货币"信用点"开卡包进货，鉴定卡的真伪和品相，卖给 NPC 顾客。营业日由玩家自己推进（学《深空当铺》）：每天来 8–12 位顾客、一位一位进门，接待完就打烊进入下一天；每 7 个营业日交一次摊位费（从 3,800 起，每次涨 22%，第 8 次封顶；新手任务帮新玩家撑过第一周）。交不起先变卖手上的卡，实在不够才破产重开；攒够 31,000 可以买下店铺、不再交租。
- **卡牌**：每张卡有隐藏属性（真伪、品相、来源）。鉴定分两条线：
  - **真伪鉴定**：查真假和是不是赃物。鉴定机构 100% 准，但赃物会被没收。
  - **品相评级**：送去"评级社"打分，参考现实里的 PSA / BGS：出 1–10 分加四个分项，评过的卡封进壳里，按分数卖高价。拿假卡去评级会被拒评，还要扣信誉。
- **收集**：卡牌永久保留，可以卖给 NPC，也可以玩家之间用信用点自由定价交易。图鉴分四层（普通、每种风格各一张、9 分以上封壳、编号限定），每个赛季出新系列，越收越厚。
- **软赛季**：8 周一个赛季，但**赛季末什么都不清空**（卡、信用点、店铺、科技树都保留）。赛季只是排名周期：按本季新拿的"赛季积分"（图鉴、成就、经营里程碑）排名，赛季末每个参与的人都拿 10 包卡包，名次越高其中"星冕 / 星尘"赛季卡包越多（第 1 名 10 包全是星冕，第 11 名以后是 1 包星尘加 9 包自选系列的普通卡包）。赛季卡包里有只能靠赛季排名或玩家交易拿到的赛季限定卡（每季 5 张）。
- **NPC 顾客**：每个营业日 8–12 位（平均 10 位），一位一位进门，有学生、观光客、收藏家、怀旧老顾客、炒卡客、开箱主播等 9 类，价格和讨价还价全由服务器代码算。顾客台词提前用 AI 批量写好、人工挑过存成表，游戏运行时不调用 AI。
- **科技树**：店铺升级，五条分支（柜台、鉴定、进货、电话、店面），32 个节点，最深 6 层，用信用点单向换成"蓝图"来点，还要满足信誉或里程碑条件。每赛季可以花信用点买一次"改换门庭"，蓝图全部退回、重新点。中途要在"正经店"和"销赃窝点"两条路线里选一条。电话分支是一个来电事件系统（预约客、线人、回电等）。永久保留（赛季不清空），破产也保留。整棵树约 35 万信用点，是信用点的主要消耗口，让玩家赚来的钱有地方花，不只是拿去兑金币。
- **节奏**：想玩几天玩几天，一个营业日几分钟，异步玩，面向几十到几百人的社群。**因为营业日不跟现实时间走，玩得多的人信用点赚得多，每个现实周兑出的金币靠每周 2,000 的上限兜底。**
- **没有付费内容**，不卖卡包，金币买不到任何游戏内东西。

完整设计（DESIGN.md）和实现规格（SRS.md）需要的话可以找我们要。所有数值都是初版，上线前会用经济模拟脚本验证。

## 2. 和旺财的关系（只有这一处碰金币）

**信用点可以单向兑换成旺财金币，金币不能换回信用点。**

| 规则 | 现在的提案 |
| --- | --- |
| 汇率 | 10 信用点 = 1 金币 |
| 每人每周上限 | 2,000 金币，每周一 00:00（悉尼时间）重置 |
| 方向 | 只能信用点 → 金币 |
| 交租宽限期内 | 不能兑 |
| 租金保证金 | 只能兑超过下次租金的那部分信用点（防止有人把交租的钱兑走再故意破产，模拟验证过） |
| 赛季末的信用点 | 不清零（软赛季），继续留着用 |

**为什么只开这一个方向**：金币买不到卡包，就不会变成拿服务器金币去赌概率（你们讨论金币买经验时担心过 Discord 赌博风险）。

**金币产出量级**：我们有意把卡奴调得比较"爽"，要有开卡暴富的感觉。

- 只走保守路线的人，按经济模拟（1,000 个赛季），每周交租前净赚中位约 9,500 信用点（约 950 金币），平均约 14,700（约 1,470 金币）。差距来自运气：开到 UR 以上大卡的那周会多赚很多。同时约 15% 的人一季里会破产一次，约 70% 能买下店铺。
- 玩得最好的人，一周最多兑出 2,000 金币（每周上限）。
- 作为对比，旺财里活跃玩家每天签到加工资大约拿 50 到 300 金币，一周 350 到 2,100。

兑换上限是限住金币产出的唯一阀门，爆率和游戏内数值只影响信用点。我们预计游戏好玩的话，玩家平时会把信用点花在开包、买店和科技树上，不急着兑。信用点不清零，所以不会有赛季末集中兑满的峰值。

**不玩也能白拿金币吗？不能。** 开局有 1,500 信用点，破产重开给 1,200，第一周租金 3,800。因为有租金保证金（只能兑超过下次租金的部分），一个什么都不玩的人一枚金币都兑不出来。

## 3. 需要在旺财里加的东西

我们**不 import 旺财的任何代码**，只通过 control-server 的 HTTP 接口调用（和牌局 live 模式一样，127.0.0.1 + `Authorization: Bearer <CONTROL_SECRET>`）。

需要新增一个接口：`POST /wallet/cardshop-redeem`，参数 `{ key, userId, coins }`。打算这么改：

1. `src/wallet-core.js`：`WALLET` 加 `cardshop: { rate: 10, weeklyCap: 2000 }`；新增 `cardshopRedeem(s, { key, uid, coins, week, now })`，`week` 是调用方传的悉尼时间该周周一的日期。
   - 用 `once()` 做幂等；未开户返回"还没开户（进服满 3 天自动开户）"；`coins` 必须是正整数；本周累计超过 `weeklyCap` 就拒绝。
   - 周累计不能放 `s.daily`（`rollDay` 每天清空），打算单独加 `s.cardshop[uid] = { week, coins }`，并加进 `normalizeWalletState` 的字段清单。
   - 用 `credit(s, uid, coins, 'cardshop', null, now, ledger)` 入账，流水 `why = cardshop`。
2. `src/index.js` 的 `walletApi` 加 `cardshopRedeem({ key, userId, coins })`，照 `prop` 的写法：`walletEnsure` → 内核 → `walletFinish`。
3. `src/control-server.js` 的 `handleWallet` 路由表加 `'/wallet/cardshop-redeem'`，文件头接口清单补一行。
4. `scripts/wallet-drill.mjs` 补用例：同一个 key 只入账一次、超额拒绝、未开户拒绝、非正整数拒绝。

卡奴这边的处理：先扣信用点、记一张 pending 兑换单，再调旺财。旺财明确拒绝（`ok:false`）才退信用点；超时、连不上、5xx、404 都保持 pending，每 10 分钟用**同一个 key** 重试。pending 超过 24 小时就报警，转人工处理。

我们核对过的旺财行为（请确认没理解错）：

- `handleWallet` 对业务错误一律回 HTTP 200 + `ok:false`；钱包没开回 503。
- `once()` 连拒绝结果也会记住，同一个 key 重试拿到的结论不变。
- `seen` 只保留 48 小时（`WALLET.seenTtlMs`），所以卡住的单子必须在 48 小时内处理完。
- `GET /wallet/<id>` 会顺手给够格的人开户（`walletEnsure`）。卡奴首页会调它来显示金币余额。

## 4. 待确认的问题

### A. 金币和经济

- **A1** 汇率 10:1、每人每周 2,000 金币的上限，可以吗？保守玩家每 7 个营业日中位约 950、平均约 1,470 金币；营业日由玩家自己推进，玩得多的人每个现实周会碰到 2,000 的上限。这个量级你能接受吗？
- **A2** 卡奴里玩家之间可以用**信用点**自由定价买卖、交换卡牌，全程不碰旺财金币。我们理解这和牌局"金币不能在玩家之间转账或赠送"的红线不冲突，对吗？有没有别的顾虑（比如有人借交易给小号送信用点，再兑成金币）？
